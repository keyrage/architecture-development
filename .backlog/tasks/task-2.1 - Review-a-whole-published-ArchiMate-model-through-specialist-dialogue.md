## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Users need an initial useful outcome before governed model mutation exists: an independent assessment of the complete current active published semantic model, followed by user-directed discussion. The extension must work across the full ArchiMate 3.2 lexicon while leaving formal metamodel validation to Archi, preserve every specialist finding, and keep model credentials secret.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The user selects a vault-configured model, expected ArchiMate groups (Application and Technology by default), and any non-empty subset of the six available specialists (all six by default)
- [x] #2 The complete current active published model is processed in bounded chunks without silent sampling or mixed-revision evidence
- [x] #3 The user is shown completeness, cross-layer traceability, documentation, Motivation/strategy, repository-alignment, and advisory-derived-relationship specialists with descriptions; only the selected specialists run, in parallel when supported and sequentially otherwise
- [x] #4 A synthesizer preserves the selected specialists' original and deduplicated findings, globally ranks every resulting recommendation with an explained impact/confidence/scope/effort score, and presents strengths plus the top ten in the agent UI
- [x] #5 The user can choose a recommendation, request follow-up from a selected specialist, record a concise accepted/rejected/deferred/needs-investigation rationale, stop, and resume; changing the specialist selection starts a fresh review epoch without rewriting history
- [x] #6 Findings cite canonical model IDs and applicable referenced repository paths and line ranges; unreferenced repository content is not inspected during initial assessment
- [x] #7 A changed published revision triggers one automatic restart during collection and requires a fresh assessment on resume while preserving prior review history
- [x] #8 Synthetic tests cover the query contract, chunking, restart behavior, full ArchiMate 3.2 input vocabulary, specialist defaults/subsets/invalid selections, exact selected-role recording and follow-up, ranking, dialogue, durable records, sequential fallback, and credential non-retention
- [x] #9 Live smoke testing copies and checksum-verifies only an accepted Archi Software Factory plug-in archive, builds an otherwise independent disposable Archi/Memgraph environment, exercises only public read-only boundaries, retains no credentials, and cleans up on success or failure

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. **Build this as a publication-ready MIT-licensed Swamp Club extension.** Use a root `manifest.yaml` for `@keyrage/architecture-development`, a registry-derived CalVer, concrete description, truthful platform declaration, public repository URL once configured, the model and skill entries, and root `README.md` plus the canonical MIT `LICENSE` in `additionalFiles`. Follow Swamp Club's hermetic import rules: inline `npm:zod@4`, pinned static non-local imports, module/export JSDoc, explicit public return types, and colocated `*_test.ts` suites.
2. **Represent selectable models safely.** Use one tracked `@keyrage/architecture-development/review` definition per configured Archi model. Persist non-secret model ID, endpoint-file path, optional repository root, and only a sensitive `${{ vault.get(...) }}` reference for the bearer token. Listing displays only definition metadata and never resolves tokens; execution reports missing or revoked credentials without revealing values.
3. **Collect complete revision-coherent evidence before writing.** Validate bounded pages for discovery, folders, elements, and relationships into a method-run temporary staging tree. Write no resources until every cursor, count, endpoint, model, revision, capability, and limit invariant succeeds. Delete the first staging tree and restart once after revision movement; fail before durable writes on a second movement. Only then write `evidenceChunk` instances and `evidenceManifest`; use `rollbackOnFailure` for final-write failures and remove staging in `finally`.
4. **Persist a resumable review lifecycle.** Use valid camelCase specs: `reviewState`, `evidenceChunk`, `evidenceManifest`, `specialistAssessments`, `synthesis`, `followup`, and `disposition`. Prefix each globally unique instance name with its spec and include validated review ID, epoch, and sequence/record ID where applicable. Store the confirmed specialist selection immutably per epoch. Add guarded methods for start, status, collection, atomic assessment recording, synthesis, follow-up, disposition, stop, and resume. Revision or specialist-selection changes create a fresh epoch while preserving history.
5. **Let the user choose specialists, then synthesize deterministically.** Present the six fixed roles with descriptions and all selected by default. Accept and confirm any non-empty subset, store it canonically for the review epoch, and run only those roles in parallel when supported and sequentially otherwise. Normalize results to canonical specialist order, record exactly one per selected role, and reject missing, duplicate, or unselected results. Require the synthesized source-finding set to equal the complete selected-assessment finding set so none can be omitted or invented. Rank recommendations using `impact*4 + confidence*3 + scope*2 + (6-effort)` (10–50), with the defined deterministic tie-break.
6. **Constrain repository evidence and dialogue.** Inspect only normalized executable-design target paths contained under the selected repository root, cite exact paths and line ranges, and report the lens as not assessable when no references exist. Let the user explicitly select recommendations and record accepted/rejected/deferred/needs-investigation/undecided dispositions; never infer approval.
7. **Run Swamp Club adversarial review before testing.** After authoring, perform mandatory mechanical schema/write, truncation, instance-name, and schema-field checks, followed by all universal and model-specific review dimensions. Use `swamp extension push manifest.yaml --dry-run` to obtain the content-hash-bound report skeleton, complete it, present findings, and wait for user acknowledgment before smoke or unit tests. Any source/version change repeats the affected review and regenerates the report.
8. **Verify with documented tools and an independent live environment.** Use bundled Deno for documentation, type, format, lint, colocated tests, and synthetic smoke. Live smoke reads exactly one explicitly supplied accepted `.archiplugin` file—even when under the sibling immutable acceptance directory—copies it immediately, and verifies the supplied SHA without enumerating or consuming any other sibling path. It then independently provisions pinned Archi and creates run-scoped HOME/XDG, model fixture, Memgraph container/volumes, endpoint, and a newly initialized Swamp repository/configuration/local-encryption vault/source-loaded extension/model definition. Pipe the one-time token into that vault without argv, environment, or log exposure. Exercise only read-only public methods, retain redacted evidence, and trap-delete all runtime and Swamp/vault state on success, failure, or interruption.
9. **Follow the publication state machine without shortcuts.** Verify `.swamp.yaml`, authenticated `keyrage` collective and repository rights; obtain/apply `nextVersion`; format/check; run and present the informational quality score and unearned factors; complete a final fresh adversarial report and dry run; present warnings; and stop for separate explicit human approval before any real registry push. Never use `--yes` to bypass review warnings.
